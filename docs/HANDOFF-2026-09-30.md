## 3. Decisions you made (keep these)

- **Read-only comes from the product.** Only the product's own `access_check` can call a login read-only. Labels, presets and skills can only make Casper more careful.
- The AI can never approve or confirm anything for you.
- **Full scope** for v0.2.16 and v0.2.17 (no cuts).
- **Stricter verified** exit code (v0.2.17).
- **Enter picks the safe choice** everywhere. Easy to undo if it annoys you.
- Plan editor asks Stop / Build (v0.2.17).
- **Everything automatic, no manual setup.** A new feature must work without the user setting anything up.
- Docs style: "Why Casper" + highlights; plain words; never "secure" or "guaranteed".
- Commits and PRs are by **secure-ssid** only. No AI tool names in commit messages or PR text.
- Skills use public vendor docs only. Nothing from work, no real hosts or tokens.

## 4. Next work: v0.2.19 (from your real-model run of v0.2.15)

What you saw with a real model, and what to fix:

1. **The AI ran `ssh` as root to a LAN host and read `~/.ssh/config` without asking.** In v0.2.15
   nothing stopped it. Check that v0.2.16's file guard and v0.2.17's sandbox stop both (the shell
   can't read `~/.ssh`, and a new host asks), and add a test that does exactly this.
2. **A plaintext `user / password` line in a markdown doc was not hidden.** The scrub only covers
   known formats and config files; add this shape (a login and password in prose or a table in
   `.md`) without hiding normal words.
3. **Folder picker:** offer to create the typed name when no folder matches, and don't show `..`.
4. **`/project <name>`** should switch to that project, or create it when it does not exist.
5. **"new project …" wording** in a request should reach the new-project question.
6. **"Changes unknown" in a huge non-git folder** needs a plain message saying why (too many
   files to compare) and what to do.
7. **Quieter tool lines:** hide durations under one second, and show one line per tool call.
8. **Short labels for long bash commands** in the tool lines.
9. **The leftover "Working" box** after a receipt (seen again with a real model).
10. **tmux:** detect it on its own. Put helpers in view-only panes only when Casper already runs
    inside tmux or iTerm2; never start tmux. Add a `/tasks` list of what is running. Document it.

Owner rule for all of these: everything automatic, no manual setup.
