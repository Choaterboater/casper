Casper vs plain Pi

Casper is built on the Pi SDK. So what does it add, and when is plain Pi the better tool? Here is the honest version, with the good and the less good.

First, what is Pi?

Pi is a small terminal coding agent. Out of the box it gives the AI four tools: read, write, edit and bash. Its idea is "keep the core small, add what you want". It has no MCP, no permission pop-ups, no sub-agents and no plan mode built in. You add those yourself with extensions, skills or Pi packages.

Casper uses Pi's SDK as a pinned library (Pi 0.87.0 in Casper 0.2.15). It is not a fork and not a Pi extension. Casper wraps the AI's work in a loop of checks, proof and a receipt, and adds guard rails for network gear.

The Casper loop, in one picture

The AI does the edits. Casper does the checking. "Done" is the AI's claim; the receipt is what really happened.

  1. You ask. In plain words, like fix the sum bug in src/sum.js. For code changes in a chat, Casper first lists the cases your request states, so the AI's tests cover them. You can edit or skip that list.
  2. The AI edits files. Pi's engine does this part underneath.
  3. Casper runs your checks. Your project's own test, lint, type check and build commands. It finds them by itself for Node, Python, Rust and Go projects, or reads them from .casper/project.yaml. No model call for this part.
  4. Proof. Casper runs the tests on a copy of the project without the change. If they fail there and pass with it, the change is proven.
  5. Receipt. Line 1 is the verdict: Verified, Not verified, Failed and so on. The lines under it are the evidence.

Where plain Pi is better

Casper is not the right tool for every job. Plain Pi wins here, and that is fine.

Lighter

Four tools, a short prompt, no extra steps. Nothing runs after the edit unless you ask. Less to learn, less to go wrong.

Faster for tiny edits

Fix a typo, rename a thing, tweak a comment: Pi is done when the edit is. Casper runs checks and a proof run on top. (You can start Casper with --no-verify, but then why not use Pi?)

Its own extensions

Pi's whole idea is "build it your way". Custom tools, commands, UI, even games while you wait. Pi packages install from npm or git. Casper does not import them.

More providers and modes

Pi lists many model providers, plus RPC mode and a session tree (/tree, /fork). Casper's /login offers four providers.

Casper and other AI coding tools

We won't name other tools or guess at their insides. Here are fair, general points instead.

  • Many tools report "done" without running your tests. Casper runs your project's own checks after each code change, by default.
  • A green test run does not always test the change. Casper checks that the tests fail without it. If they don't, the receipt says Not proven.
  • Many tools end with a friendly summary. Casper ends with a receipt whose first line is a verdict, and it says "Failed" or "Not verified" when that is the truth.
  • Network gear is not a toy. Casper starts MCP servers with writes off, asks before each change, and hides known device secrets from the AI.
  • Some tools do some of this too. Casper does not claim to be the only one. It is one careful way to do it, in the open, under the MIT licence.

What about numbers?

No full, measured benchmark yet

Casper has an evaluation suite (evals/) that can compare Casper and Pi on the same model and the same tasks. It has not been run as a full, measured benchmark with a real model across all its tasks. So this page makes no "X% better" claim.

There are small trial runs with real models, written up in docs/evals. They are too small to call a result, but they taught us two honest things:

  • "Verified" is not "everything you asked is done". It means the checks passed and the tests prove the change. On one hard set of tasks, Casper said Verified on 12 runs that were still wrong: each skipped a case that no test covered. That is why the request checklist exists. In the same test set it cut wrong runs from 7 of 48 to 2 of 48. Plain Pi had 3 of 48 there, so that is "about the same", not "better".
  • Casper often takes longer than Pi. Checks, proof and the checklist all cost time, and sometimes tokens. That is the trade.

So: read the receipt, and still review important changes yourself.

Which one should I use?

Pick plain Pi if…

  • you want a small, fast tool and like building your own extras;
  • most of your edits are tiny;
  • you use Pi packages or a provider Casper's /login does not offer.

Pick Casper if…

  • you want your tests run and the change proven before you hear "done";
  • you connect MCP servers to network gear and want writes off until you say so;
  • you script runs and want a verdict and an exit code, not just text.

Both can live on the same machine. Casper keeps its own sign-ins in ~/.casper/agent/, separate from Pi's. See the tour for more, or the roadmap for what is coming next.
