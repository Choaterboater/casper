The coding agent that proves it's done.

A coding helper for your terminal. Build web apps, APIs, command-line tools and scripts in the language your project uses, and Casper checks the AI's work before it tells you "done". Network engineers get extra care built in.

What "done" looks like

Every coding task ends with a short receipt, and line 1 is the verdict. Casper doesn't take the AI's word for "done": it runs your project's own tests, lint and build, and where it can, it proves the change: the tests fail without it and pass with it.

✓ Verified
The checks pass and a test fails without the change.
⚠ Checks passed — not proven
A green test that was green before is not proof.
✗ Failed
Anything less than Verified says why.

A passing check shows a command passed, not that the code is fully right. Review important changes yourself. More in the tour: receipts, proof.

What it does

Builds anything

Web apps, APIs, CLIs and scripts in your project's language. casper new starts one with tests and a first commit, no tokens used.

Sees your web app

Starts your dev server, opens the page in a throwaway browser, clicks, types and takes screenshots, then replays the same check after a fix.

Checks and repair

After edits, Casper runs your checks and sends real failures back for a few repair tries (3 by default). A check that timed out or could not start is never sent to a paid repair.

Undo

Casper keeps a copy of your folder before each task. /undo, /redo and /diff work on any saved task, also outside git.

Secrets hidden

Passwords, RADIUS and TACACS keys, PSKs and SNMP communities in known formats are swapped for <secret hidden>. Not every secret, so still look before you share.

A sandbox, and asks

The AI's shell asks before commands that change things; turn the sandbox on (sandbox: on) and on macOS and Linux it and your checks run in one. Before the AI's shell reaches another machine over ssh, Casper asks, and an ssh password goes to ssh only, never to the AI.

Made for network engineers

Casper works with MCP servers such as hpe-networking-mcp, junos-mcp-server, Mist and NetBox. Casper can set up its own server for Mist, Central and ClearPass in one step (/mcp setup network). Writes start off. A login counts as read-only only when the product itself says so; anything else shows access not checked.

Building your own MCP server? casper mcp check runs its tests and checks its labels, schemas and example configs.

Good to know

  • Sign in with OpenRouter, Anthropic (Claude), OpenAI Codex or GitHub Copilot, or point it at a model on your own computer or another one. You are not tied to one model company.
  • The AI's shell asks before each command that changes something, and a write outside the project asks first. Checks run your project's own commands with your own permissions.
  • Turn the sandbox on (sandbox: on, or /sandbox on for a session) and on Linux and macOS the shell and checks write only the project, temp and package caches. Windows has no sandbox yet.
  • Your code and chat may go to the model provider you picked. The FAQ has more.

New in 0.2.32

  • A model server on another computer is added from /model (+ Add server) or /login by typing its address, with no key and no file to edit.
  • In a folder over 20,000 files, a task offers no undo or /diff, and when Casper's edits there sit in one project, that project's checks run.
  • The footer says when a newer Casper is out, until you update. A dropped macOS screenshot goes as a picture, and a page that doesn't fit a phone tells the repair why.
