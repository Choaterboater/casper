Casper

A coding helper for your terminal. Build web apps, APIs, command-line tools and scripts in the language your project uses, and Casper checks the AI's work before it tells you "done". Network engineers get extra care built in.

Why Casper

  • It builds anything you'd build in a terminal: web apps, APIs, CLIs and scripts, in TypeScript, Python, Go, Rust or whatever your project uses. casper new web-app (React with Tailwind), casper new vite-react or casper new python-cli starts a project with tests, with no model call.
  • It does not take the AI's word for "done". It runs your project's own tests, lint and build.
  • Where it can, it proves the change: the tests fail without it and pass with it.
  • Every coding task ends with a short receipt. Line 1 is the verdict.
  • It is careful around network gear: MCP servers start with writes off, and risky actions ask you first.
  • Known device secrets become <secret hidden> before the AI sees them (best effort, known formats only).
  • Sign in with OpenAI Codex, GitHub Copilot, Anthropic (Claude) or OpenRouter. You are not tied to one model company.

Highlights

The short version. Each card opens that part of the tour.

✚

Builds anything

Web apps, APIs, CLIs and scripts in your project's language. casper new starts one with tests and a first commit, no tokens used.

 ◱

Sees your web app

Starts your dev server, opens the page in a throwaway browser, clicks, types and takes screenshots, then replays the same check after a fix.

 ⌘

Knows your code

Language servers report errors right after each edit, a step debugger stops at a line, and read-only helpers search or review a big project.

 ✓

Receipts with a verdict

Each task ends with a receipt: Verified, Checks passed — not proven, Failed and so on. /receipt shows the detail.

 ⇄

Proof, not just a pass

Verified means the checks pass and a test fails without the change. A green test that was green before is not proof.

 ↻

Checks and repair

After edits, Casper runs your checks and sends real failures back for a few repair tries (3 by default). A check that timed out or could not start is never sent to a paid repair.

 ⌁

MCP, writes off

Every MCP server starts with writes off. Each change asks you in plain words: 1 No · 2 Yes, this once · 3 Yes, for this session. The AI cannot approve anything for you.

 ✱

Secrets hidden

Passwords, RADIUS and TACACS keys, PSKs and SNMP communities in known formats are swapped for <secret hidden>. Not every secret, so still look before you share.

 0

Zero-token commands

/verify, /mcp, /diff, /receipt and local reference search make no model call, so they use no tokens.

 ⌕

Local references

Search your own copies of vendor specs and SDKs (Junos YANG, pycentral, mistapi) with /references search. The AI can search them too.

 1

Numbered choices

Questions show numbered answers. Press the number to pick, or Esc to skip.

 {}

Scripts and CI

--json streams events. Exit codes tell a script what happened, for example 3 = not verified with --require-verification.

 ⑂

Sessions and branches

Pick up a past chat with --continue or /resume, or try an idea in a named branch with its own Git worktree.

What "done" looks like

A real Casper 0.2.15 run. The AI here is a scripted stand-in so the capture is repeatable, but its edit is real, and every line after it is the real Casper code: the check, the proof and the receipt.

A passing check shows a command passed, not that the code is fully right. Review important changes yourself.

Made for network engineers

Casper works with MCP servers such as hpe-networking-mcp, junos-mcp-server, Mist and NetBox. Casper can set up its own server for Mist, Central and ClearPass in one step (/mcp setup network). Writes start off. A login counts as read-only only when the product itself says so; anything else shows access not checked. Building your own MCP server? casper mcp check runs its tests and checks its labels, schemas and example configs.

Good to know

On Linux and macOS the AI's shell and Casper's checks run in a sandbox: they write only the project, can't read ~/.ssh, and reach only listed hosts. Windows has no sandbox yet; there the AI's shell asks before each command that changes something (reads like ls don't). Checks still run your project's own commands without asking. Use it in projects you trust, or start with --no-verify. Your code and chat may go to the model provider you picked. The FAQ has more.
