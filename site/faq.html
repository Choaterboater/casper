The basics

Is Casper free?

Casper itself is free and open source, under the MIT licence. The AI model is not Casper's. You sign in with a model provider, and that provider's plans and charges still apply. There is no hard spending cap in Casper.

Lots of things cost zero tokens: the checks Casper runs, /verify, /mcp, /diff, /receipt and local reference search make no model call. When a choice will spend tokens, it says the model does it, for example Fix it anyway · ask the model to make it pass; a suggestion whose words don't say so ends in (uses tokens).

Which AI models can I use?

Type /login and pick a provider:

  • OpenRouter (many model makers behind one sign-in)
  • Anthropic (Claude)
  • OpenAI Codex
  • GitHub Copilot

If you skip /login, Casper opens sign-in on your first request and picks that provider's default model (for OpenRouter, deepseek/deepseek-v4.1-flash). /model picks another one. Casper never replaces a model you chose. Type keys or codes only in the private login prompt, never in the chat.

A model on your own computer works too: start Ollama, LM Studio, llama.cpp or vLLM and its models show in /model, with no sign-in and no file to edit. For one on another computer, pick + Add server at the bottom of /model's list and type its address. The details are in the configuration guide.

How is Casper different from Pi?

Pi is the engine under the hood. Casper embeds the Pi SDK as a pinned library. It is not a fork, and not a Pi extension. It is its own program, with its own command line and exit codes.

What Casper adds on top:

  • It runs your project's checks after the AI edits, repairs real failures, and ends with a receipt.
  • It tries to prove the change: a test should fail without it.
  • MCP servers start with writes off, and risky calls ask you.
  • Known device secrets are hidden from the AI (best effort).

Casper keeps its own sign-ins and chats in ~/.casper/agent/, apart from Pi's. On first run it copies a Pi install's API keys once. It does not copy Pi's OAuth sign-ins (they would sign each other out), so run /login for those. It also ignores a repository's own .pi/ folder. For a side-by-side view, see Compare.

Your code and your network

Does it send my code anywhere?

Yes, to the model provider you picked. Your code, tool output and chat may go there, the same as with any AI coding tool. Chats may also stay on your disk as plain text.

  • Known secrets (device passwords, keys, SNMP communities and similar) are swapped for <secret hidden> before the AI sees them. This is best effort. It knows common formats only, and it will miss some.
  • Requests Casper sends to OpenRouter carry a fixed app name (Casper), so usage is filed under Casper's app. No prompt, file or user data is in those headers. Turn off Send Casper's name to OpenRouter in /settings, or set CASPER_TELEMETRY=0.
  • Checks, /verify, /diff, /receipt and reference search run locally, with no model call.
Will it change my switches?

Not through MCP on its own. Every MCP server starts with writes off, and every change shows a box that says what it changes, then asks 1 No · 2 Yes, this once · 3 Yes, for this session, and last Yes to everything on <product> this session. Enter is No; otherwise destructive changes always ask, and firmware, delete and admin changes stay off until you allow them. The AI cannot approve anything for you. Ctrl+O turns writes off again at once.

Be honest with yourself about the limits, though:

  • The sandbox is a fence, not proof. On Linux and macOS the AI's shell reaches only listed hosts, and Casper asks Reach 198.51.100.20 (build-server)? before ssh, scp or rsync. On Windows there is no sandbox: the AI's shell asks before each command that changes something (reads like ls don't). With the sandbox off, a program that opens its own connection (a Python script, curl) still reaches a switch with no question.
  • A login counts as read-only only when the product itself says so (through an access_check tool). Otherwise /mcp shows access not checked.
  • A server that labels a tool that changes things as read-only is trusted on that label, unless the tool's name has a risky word such as bounce, reboot or delete.

A read-only account on the device side is still the best seat belt. More on the Network page.

Where are my network logins kept?

Only in Casper's own private file, ~/.casper/network-logins.json. Only you can read it (mode 0600), and the AI's tools and shell can't open it. Casper hands the logins to its network server when it starts, never puts them in mcp.json, and hides the tokens and secrets anywhere they turn up. You type each one yourself, hidden, the first time a product is used or with /mcp login mist (or central, clearpass); the AI can't. /mcp login mist forget removes one. No env file, nothing to edit.

Can I use my own server?

Yes. Casper's own network server is offered, never forced. Answer 1 Not now and put any server you like in ~/.casper/mcp.json: hpe-networking-mcp, junos-mcp-server, NetBox, one you built with casper new, or anything else. Casper doesn't offer its own when you already have hpe-networking-mcp, casper-network-mcp or a server named network, and the same rules hold for every server: writes start off, and every change asks you. See Hook up your servers.

Does it ask before running every command?

Not every one. Casper's approvals cover specific things: MCP calls that may change something, connecting a server, reaching another machine over ssh, a write outside the project, a host the sandbox does not know, the browser, the debugger and a few downloads. The sandbox is off unless you turn it on (sandbox: on in ~/.casper/config.yaml, or /sandbox on): until then the AI's shell asks before each command that changes something (reads like ls don't). With it on, on Linux and macOS, the AI's shell and the checks run in it (/sandbox shows what it holds, /allowed the commands you said yes to). Checks run your project's own commands without asking first. If the sandbox blocks a check (an EPERM from a test that opens a socket, say), Casper says so, does not try to fix your code, and asks whether to run the checks outside the sandbox.

When an ssh you allowed asks for a password, Casper shows its own hidden box and the password goes to ssh only; the AI never sees it (ssh_login: off turns it off).

So use Casper in projects you trust, or start with --no-verify (no Casper-run checks). /permissions shows what Casper can and cannot do.

Checks and verdicts

What does "not proven" mean?

Your checks passed. But the tests also pass without the change. So the tests did not really test it.

When that happens, Casper spends one repair round asking the AI to add a test that fails without the change, then checks again. If it still can't prove it, the receipt says so and the change counts as not verified.

Some changes need no proof: test-only, docs-only and refactor changes. The receipt says why, for example Checks passed — not proven: a refactor should not change behavior….

Does "Verified" mean my code is right?

It means two things: the checks passed, and a test fails without the change. That is a lot better than "the AI said so". But it does not prove the tests ask for the right thing. If a test checks the wrong behaviour, the change can be wrong and still verified.

A passing check shows a command passed, nothing more. Missing or old results never count as a pass. Review important changes yourself.

Why did it ask me something?

Casper stops and asks when the next step is yours to decide. In 0.2.32 that includes:

  • an MCP call that may change something (1 No · 2 Yes, this once · 3 Yes, for this session);
  • connecting an MCP server the first time, or turning its writes on;
  • setting up Casper's network server, and a product's login the first time the AI uses it;
  • a device check, before anything is sent to a device;
  • a check that timed out or could not start: stop, retry, have the model fix it anyway, or allow more time;
  • a test that was already failing before the change, before paying to fix it;
  • a model error that repeated, to retry or stop;
  • the request checklist before a code change (edit it, or Esc to skip);
  • Next: 1 Show diff · 2 Undo after each task (Enter runs nothing; not in a folder too big to compare);
  • before the AI's shell reaches another machine, or writes outside the project;
  • a shell command to a host the sandbox does not know;
  • a retry on your big model when repairs run out, with a rough cost;
  • showing the AI the page screenshots, once a session (it uses tokens);
  • a picture in your request when the model can't see pictures: send without it, or switch for that request;
  • a public link for /preview (your network needs no question);
  • each fix casper doctor offers;
  • the first time the AI looks at this repo's pull requests and CI on GitHub, and before it re-runs failed checks;
  • an ssh password, in Casper's own hidden box (the AI never sees it);
  • adding a pack, after it shows what the pack brings (1 No · 2 Yes, add it · 3 Show me what's inside);
  • which product, when you type /mcp login on its own;
  • building a request as a new project when you started in a folder that holds other things (an empty folder asks nothing).

Answers are numbered: press the number. Esc skips. Choice 1 is always the one that does nothing risky.

Install, update, uninstall

My Mac or Windows warns me about the download. Is that normal?

Casper's programs are not signed yet. So Windows SmartScreen or macOS Gatekeeper may warn you. That part is expected for this preview.

  • On macOS, the install.sh command clears the quarantine flag for you (best effort), so the first run is not blocked.
  • Both installers check the file's SHA-256 against the release's SHA256SUMS. A mismatch stops the install, and nothing is installed.
  • Once Casper has a release key, both installers and casper update also check the release's signature over SHA256SUMS. A bad one stops the install, and your old install stays. That signs the list of files, not the programs, so it does not stop these warnings.
  • Do not click past a warning you did not expect. Check the file came from github.com/Choaterboater/casper/releases.
How do I update?

Run casper update. It finds the newest preview and runs that release's own installer, with the same checks. casper update --check only says whether there is one, and a session tells you in one line when one is out, and keeps a short note at the end of the footer until you update (Casper 0.2.33 is out · casper update). Nothing updates on its own. The install commands pin a version: running the v0.2.32 command again just reinstalls v0.2.32.

If a new download fails any check, your old install stays as it was.

How do I uninstall it?

There is no uninstaller. Nothing is installed system-wide and no admin rights were used, so removing it by hand is quick.

macOS / Linux: delete the program. The installer puts it in ~/.local/bin unless you picked another folder with --dir.

macOS / Linux
rm ~/.local/bin/casper

Windows: delete the folder %LOCALAPPDATA%\Programs\casper, then remove it from your user PATH (the installer added it there).

Settings, sign-ins and saved chats live in the .casper folder in your home folder. Delete it too if you want them gone. Projects you set up may also have their own .casper/ folder.

macOS / Linux, optional
rm -rf ~/.casper
Where are the settings?

All optional. Casper works with none of them.

FileWhat it is for
~/.casper/config.yamlYour global settings
~/.casper/profiles/<name>/A named set of settings, for example one for work and one for the lab
<project>/.casper/project.yamlOne repository: check commands, verification mode, repairs
<project>/.casper/rules.mdExtra instructions for the AI in that repository
~/.casper/mcp.jsonYour MCP servers
~/.casper/agent/Sign-ins and chats (Casper manages this)

Later ones win: defaults, then global, then profile, then project. A bad value stops loading with an error that names the file and key. Full list: CONFIGURATION.md.

Everything else

Can I use it in scripts or CI?

Yes. casper "your request" runs once and exits. --json streams events as JSON Lines. Exit codes tell the script what happened: for example, with --require-verification a change Casper could not verify exits 3, and a command-line mistake exits 64. See SCRIPTING.md.

How do I stop it asking so much?

Type /permissions: a short screen of whether Casper is asking and what is allowed, then a box: 2 Stop asking until I quit. /permissions details has the exact way to be asked less for each kind. The short version: answer 3 or 4 in a box to remember it for the session or the project; for a folder outside the project answer 4 Yes, always for this project (or /permissions write <folder>); /permissions all stops the shell's questions until you quit (the footer says ASKING OFF, and /permissions ask turns it back). There is no one switch for everything, on purpose. These stay protected whatever you pick: ~/.ssh, ~/.casper, cloud logins and shell start-up files, secrets, writes to network devices (the product login must allow them), and the AI can't answer a box for you. --no-sandbox for one run, or sandbox: off in your own config, takes the shell sandbox away too.

Can the AI look at my pull requests and CI?

Yes, on GitHub, when the folder's origin is on github.com and the GitHub tool gh is signed in (gh auth login, in your own terminal). Ask "check my PRs" or "why did CI fail on 12?". Casper runs gh itself with a short fixed list of actions (open pull requests, one pull request's checks, the failing step and last log lines, re-run failed checks). The AI never sees your GitHub login, and what GitHub sends back is marked as other people's words. The first use in a repo asks, and re-running failed checks asks first. It does not push, open or merge anything. Turn it off with GitHub tool in /settings. See GITHUB.md.

Can I add skills someone else wrote?

Yes, as a pack: /pack add <folder> or /pack add https://github.com/<owner>/<repo>@<commit>. Casper shows what is inside (1 No · 2 Yes, add it · 3 Show me what's inside) and adds nothing until you say yes. A pack holds plain text files only and nothing in it runs. Only you can add one, and a pack costs no tokens until a request fits one of its skills. Packs in /settings turns them off. See PACKS.md.

Can I change the colours?

Yes. Theme in /settings (or theme: in your own config) picks default, light (for a light background) or high-contrast. It changes colours and nothing else, and a project file can't set it. NO_COLOR still shows none.

How do I report a bug?

Open an issue on GitHub. Please include:

  • your OS (and Windows or macOS version);
  • the command you ran, and what casper --version prints;
  • the exact error;
  • whether a browser or debugger was installed.
Clean your logs first

Remove secrets and private paths before you paste anything. Casper's secret hiding is for the AI, not for your bug report.

Troubleshooting

Quick fixes for the usual bumps.

casper: command not found right after install
Open a new terminal. On macOS/Linux, if ~/.local/bin is not on your PATH, the installer printed the exact export PATH=… line to add.
casper --version shows an odd path
It prints casper <version> (<path>), so you can see which copy runs. An old copy or a source-checkout link may come first on your PATH. The installer will not replace such a link unless you add --force. On Windows, try Get-Command casper.
The installer stopped with a checksum or version error
Nothing was installed and your old copy is untouched. Try again later, and check the URL points at the Casper releases page.
The receipt says Not verified — no configured check covers …
Casper found no check for those files. /project shows the commands it found. Add yours under commands: in .casper/project.yaml.
A check says could not start (exit 127)
The tool it needs is not on your PATH. Install it, then pick Retry. Casper does not send this to a paid repair unless you pick "Fix it anyway".
The AI got Not executed (… writes are off …)
Working as designed: you turned writes off (Ctrl+O) while its change box was open, or this run can't ask you. Ask again in an interactive session and answer the change box.
/mcp shows access not checked
Not an error. The server has no access_check tool, or its answer did not say read-only, so Casper will not call the login read-only.
My Pi sign-in did not carry over
OAuth sign-ins are never copied from Pi. Run /login <provider> to give Casper its own.
No diagram files on Windows
On Windows, diagrams show in the chat instead. Diagram files need macOS or Linux.
Casper opened in my home folder
Casper opens exactly where you started it and asks nothing. From your home folder or the top of a drive it prints one line naming the project you last worked in, such as casper ~/Projects/aibot to work there, and casper new to start a new one. In any other folder, if it holds several projects, one line names them.
Casper built a template in my empty folder
Your first request fitted a template (a NOC dashboard, an MCP server), so Casper built it there and said so in one [new] line. Nothing was asked. Say "from scratch" in the request to skip it, or turn Starter templates off in /settings (templates: off). A request that fits no template just goes to the AI.
Casper says it "asks before commands that change things"
On Linux without bubblewrap and socat (and in WSL), and on Windows, there is no shell sandbox, so the AI's shell asks before each command that changes something. /sandbox or casper doctor shows the exact line to install the full sandbox. Casper fetches its own ripgrep when none is installed.
No colours or live footer
Casper switches to plain text with NO_COLOR, TERM=dumb or when output is redirected.
